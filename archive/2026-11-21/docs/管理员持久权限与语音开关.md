## 持久管理员权限

用户先报告“按钮不可点击”，随后要求配置双端管理员权限，并明确要求持久配置。两端此前的 `/api/auth/status` 均为 `write_access=false`，当前会话未填写管理员令牌；这使控制按钮按只读规则禁用。

电脑使用独立的可见 Edge 联调窗口及独立配置目录，窗口标题为“DnB26 正式联调 · 管理员 2.1.2”。用户原浏览器窗口保留，本次授权只配置了该联调窗口。网页使用同源后端 `http://192.168.137.2:8080`，地址输入留空也表示同源。

实体 APK 使用 `http://10.84.15.226:18080`，真实后端 HTTP 模式。沿用板端已有管理员令牌；未旋转凭据、未关闭鉴权，实际令牌未写入源码、证据或本文。

持久化机制：

- 网页：一年有效的 HMAC 签名 Cookie，`HttpOnly`、`SameSite=Strict`、路径 `/api`；HTTPS 源设置 `Secure`。现有 HTTP 入口没有传输加密。Cookie 写操作要求 `Origin` 与会话中的源精确一致；错误 Bearer 不回退到 Cookie。
- APK：Android Keystore 非导出密钥与 AES-GCM，加密保存后端地址及令牌。APK 禁止备份，原生桥日志关闭。启动根据加密记录恢复权限，网页存储标记丢失时也可以重建。

## 语音开关需求与实现

用户确认：禁用仅屏蔽新的语音指令，已有 5 秒语音覆盖按原规则恢复；UNO1 每次重新上电默认启用。开关不写 EEPROM，不改变 PIN。

候选首页新增“语音控制”设备和“语音”分类，按钮为“禁用语音 / 启用语音”，状态为“已启用 / 已禁用”。只读、UNO1 离线、未知状态、连接错误以及待回执期间禁用操作。前端等待回执及新快照，不先行改变显示状态；历史与首页使用一致文案。旧 Mock 数据只在内存补充缺失设备，保留原设备状态、人员及历史。

实际执行链路为：网页 / APK → 管理员鉴权 → `voice_control` → 网关 `VOICE_ON / VOICE_OFF` → UNO1 本地接收门控 → `voice_enabled` 遥测 → 数据库、双端及历史。ASRPRO 的语音指令原本在 UNO1 本地直接执行，因此必须升级 UNO1 固件才能阻止真实动作。

UNO1 启用或禁用时清除未完成脉冲组；重新启用及上电时先等待 300 ms 完整静默，避免把旧指令尾部误判为另一条指令。已复现“关门”指令在复位后尾部被误解成“开门”的旧路径，修复后同一复现不解码、不打开门。已有灯/风扇语音覆盖的截止时间和还原设置不改变，其他控制方式继续有效。

旧固件缺少 `voice_enabled` 时，后端不生成默认已启用遥测，不宣告此能力，并拒绝语音开关命令。当前线上仍是旧固件，因此新增语音项的实机验收尚未开始。
