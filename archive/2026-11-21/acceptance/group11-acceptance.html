遥测上行

UNO 采集并上报，电脑网关归整后提交给 FastAPI。MySQL 按本次实际收到的字段更新，各指标保留自己的采样时间。双端读取同源快照、历史与报警。

命令下行与回执

后端生成命令 ID，网关按板下发，UNO 回送 ACK 和后续状态。命令 ID 串起请求、回执与设备事件，门体是否机械到位仍由现场观察。

软件实现

一套 API，两端共享设备状态

React、TypeScript 与 Vite 共用同一套前端，Capacitor 封装 Android。FastAPI 处理权限、设备命令、视觉与历史，MySQL 保存现场业务数据。

FastAPI 与 MySQL

后端维护统一快照和命令状态，入口集中在 backend/system_routes.py。MySQL 保留组员交付的四张基础表，并增补命令、设备明细、事件、设置和报警等业务存储。数据库不可用时，接口返回明确错误。

状态与历史可读，设备控制、人员修改、配置和报警确认须经管理员授权。网关使用独立身份认证。报警的“已确认”和“已恢复”分别记录。

DNB1 与设备反馈

Windows 网关入口为 integrations/hardware/gateway/client.py。USB 串口 9600 8N1。下行包含命令编号、操作码和参数，上行分为身份、状态、ACK 与现场事件。

每块板同一时刻只有一条未确认命令，串口下发至少间隔 1.1 秒。普通命令有效期 5 秒，领取一次，超时显示结果未知。两块板独立判离线，对应设备控制随之受限。

现场排障与修复
  • 手机无法直达板端时，采用 Windows 热点转发入口。先用手机浏览器请求状态接口，再检查 APK 的地址与 HTTP 模式。
  • Android 媒体由共用服务读取，通过 Blob URL 展示，并处理超时、取消和资源释放。
  • UNO1 的 30°C 开／28°C 关由固件执行。阈值下发后的“已同步”以 UNO1 后续遥测为准。

视觉运行时

USB 相机实测采集 640 × 480。Ascend NPU 运行两套目标检测模型，CPU 执行人脸检测、特征提取与眨眼判定。

离线部署与回退

  1. Windows 准备并校验 ARM64 依赖、模型和前端静态构建。
  2. 板端在独立 Python 环境运行，将代码与静态资源放入 releases/ 下的版本目录。
  3. 用 current 软链接切换启用版本，数据库、人员资料、模型和配置保存在 shared/。
  4. 回退时切回旧代码版本，再核对服务状态、共享数据兼容性和端到端行为。

API、Web 和 MySQL 通过 systemd 用户服务管理。启用 linger 后服务可独立于 SSH 会话常驻。Windows Time 为板端提供局域网 NTP，校准历史记录的时间基准。门禁与灯效的动作时效由单调时钟判断。

边缘视觉

同一摄像头，两条实时识别链路

一个采集服务持有摄像头，目标检测与人脸线程各自取最新帧。识别结果携带帧号与采集时间。动作派发前再次检查采集会话与帧时效，联动帧最长年龄为 1.5 秒。

Ascend NPU

YOLO11n 目标识别与灯效

COCO 通用模型用于人员、汽车等类别，自定义模型识别无人机、灭火器和灯泡。同一帧顺序经过两个目标模型，识别结果保留模型来源。

PyTorch PT→ONNX→Ascend OM

训练在 Windows 的 RTX 4060 Laptop GPU 完成。ONNX 由 ATC 编译为 Ascend310B4 OM，同名 JSON 提供类别映射。初始三类导出输入为 1×3×640×640，输出为 1×7×8400。

现场动作 实时连续三次识别灯泡后，主灯转为青色常亮，亮度 80%，沿用当前灯珠数量。

CPU · HOG 与人脸特征

登记身份、眨眼与入户门

登记照片提取 128 维人脸特征。实时画面要求单一授权人脸，匹配分数门限为 0.65，对应欧氏距离上限 0.35。会话内复核身份连续性。

身份匹配→睁 · 闭 · 睁→门控反馈

68 点关键点用于计算眼睛纵横比。判定阈值 0.23，验证窗口 15 秒，闭眼至少一个处理帧。换人、遮挡、掉线或超时使会话失效。

现场动作 通行后进入冷却，等待本次门控制器上报开门再关门。上传照片和本地回放属于分析模式，通行与灯效由实时摄像头路径触发。

现场演示 · 建议 6 分钟

从一次控制到两条视觉联动

投屏打开 Web，手机打开同一后端的 APK，实物与摄像头置于可观察位置。每一步对照页面状态、回执与实体动作。

  1. 约 1 分钟

    核对双端与环境读数

    打开首页与系统页，确认 API、数据库、相机和双 UNO 状态。对照两端同一次温湿度与光照采样。

  2. 约 1 分钟

    控制主灯或风扇

    从 Web 调整一项设置，观察待确认到 ACK、实体动作和手机状态更新。风扇默认迟滞阈值为 30°C / 28°C。

  3. 约 1 分钟

    展示目标识别与灯泡联动

    将预先验证过的灯泡样例放进实时摄像头视野，展示类别框、青色 80% 灯效和两端记录。

  4. 约 2 分钟

    核对入户门放行与拒绝

    已登记人员真人眨眼，观察两个客户端的验证反馈、门开和约 5 秒后自动关闭。再展示未登记人员的拒绝路径。

  5. 约 1 分钟

    回看历史与报警

    双端查询同一时间段的实物操作。用一条既有报警说明故障状态和人工确认如何分别记录。

现场连接异常怎么讲

若仅手机无法连接，先核对热点转发地址和手机连到的网络，再用手机浏览器访问状态接口。若板端无法连接，用离线原型照片、界面示意和联调记录说明各条链路，并说明现场未复现的步骤。
