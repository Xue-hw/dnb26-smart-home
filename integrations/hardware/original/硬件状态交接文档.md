# 智能家居项目 — 硬件当前状态与软件联调交接文档

> **说明**：本文档基于当前硬件代码整理，用于硬件组与软件组（电脑中转 + 香橙派端）对齐现有功能、引脚资源及后续有线联调的接口需求。

---

## 一、总体硬件架构

目前硬件端由 **两块 Arduino UNO** 组成，采用**有线连接方案**：两块 UNO 通过 USB 线连接至电脑（使用 `D0`/`D1` 硬件串口，波特率 `9600`），再由电脑端与香橙派进行通信与控制转发。

| 板卡编号 | 对应代码文件 | 负责子系统 |
| :--- | :--- | :--- |
| **UNO1** | `Uno1_Environment_Garage/Uno1_Environment_Garage.ino` | 室内环境监测（温湿度、光照）、智能台灯、温控风扇、ASRPRO 语音识别、OLED 显示、入户门密码锁与舵机 |
| **UNO2** | `Uno2_RFID_Door/Uno2_RFID_Door.ino` | 车库 RFID 刷卡门禁、蜂鸣器提示、车库门舵机 |

## 二、UNO1 详细状态（室内环境与入户门禁）

### 1. 已接外设与引脚占用
| 引脚 | 连接模块 / 用途 | 备注 |
| :--- | :--- | :--- |
| `D0` / `D1` | **空闲（预留串口）** | 当前用于 USB 串口打印与指令接收 |
| `D2` | ASRPRO 语音模块信号线 | 外部中断 `CHANGE` 边沿脉冲计数 |
| `D3` | DHT11 温湿度传感器 | 每 `2000ms` 读取一次 |
| `D4` | NeoPixel RGB 灯带 | 代码配置 `8` 颗灯珠，目前仅点亮第 `0` 颗暖色光 `RGB(255, 150, 40)` |
| `D5` | 风扇 PWM 控制 | 开启时固定输出 PWM=`100` |
| `D6 ~ D9` | 4×4 矩阵键盘（行） | 与 `A0, A3, A4, A5` 组成按键扫描 |
| `D10` | 入户门舵机 | 关门 `90°`，开门 `0°` |
| `D11` / `D13` | OLED SPI 数据(MOSI) / 时钟(SCK) | 硬件 SPI（SSD1306 128×64，CS 接 GND） |
| `D12` | OLED 复位 (`RES`) | — |
| `A0, A3, A4, A5` | 4×4 矩阵键盘（列） | — |
| `A1` | 光敏传感器（模拟输入） | **数值越大表示环境越暗** |
| `A2` | OLED 数据/命令 (`DC`) | — |

> **💡 引脚说明**：UNO1 除 `D0`/`D1` 外其余数字与模拟引脚已全部占满；由于采用 **USB 有线直连电脑** 方案，无需额外占用引脚接无线模块，现有 `D0`/`D1` 可直接稳定用于与电脑端串口通信。

### 2. 已实现的功能与当前逻辑
1. **温湿度监测与风扇控制**
   - 自动模式（默认 `FAN_AUTO`）：温度 $\ge 29.0^\circ\text{C}$ 自动开风扇，低于 $29.0^\circ\text{C}$ 自动关；DHT11 异常时自动停止。
   - 手动模式：可通过串口指令强制开关或切回自动。
2. **光照监测与智能调光台灯**
   - 每 `100ms` 连续采样 10 次取平均。
   - 自动模式（默认 `LAMP_AUTO`）三档调光：
     - 光照值 $\le 500$（明亮）：`0%`（灭）
     - 光照值 $> 500$（较暗）：`20%`
     - 光照值 $> 800$（黑暗）：`60%`
   - 手动模式：默认亮度 `30%`，支持 `0~100%` 无级调节。
3. **入户门密码锁**
   - 4×4 键盘输入密码 `4321#` 开门，`*` 清空当前输入。
   - 开门后延时 **`5000ms` 自动关闭**；舵机到位 `1200ms` 后自动释放（`detach`）。
4. **ASRPRO 语音控制（脉冲解码）**
   - `1` 脉冲：开风扇（临时覆盖 **`5s` 后自动恢复 `AUTO`**）
   - `2` 脉冲：关风扇（临时覆盖 **`5s` 后自动恢复 `AUTO`**）
   - `3` 脉冲：开灯（临时覆盖 **`5s` 后自动恢复 `AUTO`**）
   - `4` 脉冲：关灯（临时覆盖 **`5s` 后自动恢复 `AUTO`**）
   - `5` 脉冲：开入户门
   - `6` 脉冲：关入户门
5. **OLED 屏幕显示**
   - 每 `5000ms` 及状态变化时刷新，显示：`UNO1 Home`、DHT 状态（`DHT OK` / `DHT N/A`）、温度、湿度、风扇状态、灯光亮度与模式（`A%`/`M%`）、入户门状态（`OPEN`/`CLOSE`）。

### 3. 现有串口指令与上报格式（波特率 `9600`，`\n` 结尾或空闲 `800ms` 触发）
- **控制指令（不区分大小写）**：
  - 系统与调试：`STATUS`、`ASR TEST`、`HELP`
  - 入户门：`ENTRANCE OPEN` / `OPEN`、`ENTRANCE CLOSE` / `CLOSE`
  - 风扇：`FAN AUTO`、`FAN ON`、`FAN OFF`
  - 灯光：`LIGHT AUTO` / `LAMP AUTO`、`LIGHT ON` / `LAMP ON`、`LIGHT OFF` / `LAMP OFF`、`BRIGHT <0-100>` / `LIGHT <0-100>` / `B <0-100>`、`B+`（+10%）、`B-`（-10%）、`B?` / `BRIGHT?`
- **上行数据**：每 `3000ms` 打印一次状态行（如 `Light=... | ASR last=... | Lamp=... | Temp=... | Fan=... | Entrance=...`），期间会穿插按键、语音、动作提示等普通文本日志。

## 三、UNO2 详细状态（车库 RFID 门禁）

### 1. 已接外设与引脚占用
| 引脚 | 连接模块 / 用途 | 备注 |
| :--- | :--- | :--- |
| `D0` / `D1` | **空闲（预留串口）** | 当前用于 USB 串口打印与指令接收 |
| `D5` | 车库门舵机 | 关门 `0°`，开门 `90°` |
| `D6` | MH-FMD 蜂鸣器 | 低电平触发，刷卡开门鸣响 `150ms` |
| `D9` ~ `D13` | MFRC522 RFID 读卡器（SPI） | `D9=RST`, `D10=SS`, `D11=MOSI`, `D12=MISO`, `D13=SCK` |
| `D2~D4, D7~D8, A0~A5` | **空闲** | 引脚充足，可直接扩展软串口或其他模块 |

### 2. 已实现的功能与当前逻辑
1. **RFID 刷卡开门**
   - 检测到卡片后读取并打印 UID，触发蜂鸣器并开门（刷卡冷却时间 `2000ms`）。
   - 当前 `REQUIRE_UID_FOR_RFID_OPEN = false`，即**未做白名单校验，任意有效卡片靠近均可开门**。
   - 连续 `3000ms` 未检测到卡片会自动重新初始化 RC522 与天线以防模块假死。
2. **车库门舵机**
   - 采用逐度步进平滑开关门（每度延时 `25ms`），开门后 **`5000ms` 自动关闭**，到位 `1200ms` 后自动释放。

### 3. 现有串口指令与上报格式（波特率 `9600`）
- **控制指令（不区分大小写）**：
  - 开门：`1234`、`PIN 1234`、`CODE 1234`、`OPEN`
  - 关门：`CLOSE`
  - 状态与帮助：`STATUS`、`HELP`
- **上行数据**：每 `1000ms` 打印一次 `Garage door=OPEN/CLOSED` 及 `RC522 communication=OK/NO_RESPONSE VersionReg=0x...`，刷卡和开关门时会穿插提示日志。

## 四、有线联调前需要软件组确认的事项

目前采用 **“UNO 板子 → USB 串口 → 电脑 → 香橙派”** 的有线联调方案，在调整串口协议与代码前，请软件组确认以下 4 项内容：

1. **电脑端转发链路与端口识别**
   - **电脑 ↔ 香橙派通信方式**：确认电脑与香橙派之间通过什么方式连接与交互（如局域网/网线 TCP Socket、MQTT、HTTP API，或 USB 转串口），以及电脑端串口转发脚本由哪一方负责编写。
   - **两块板子的串口区分**：两块 UNO 接入电脑后会分配两个串口号（如 `COM3`/`COM4`），重新插拔或重启后端口号可能变化。建议约定在硬件端增加身份查询指令（如发送 `ID` 返回 `UNO1`/`UNO2`），由电脑端启动时自动扫描识别。

2. **串口通信协议格式**
   - 目前两块板子的串口输出为**人类可读文本 + 调试日志混杂**，不利于程序稳定解析。
   - 建议约定统一的结构化协议（例如 **JSON 行**，或 `DATA:` / `EVENT:` / `ACK:` 固定前缀，调试信息统一加 `LOG:`），并明确：**设备标识字段**（区分 `UNO1`/`UNO2`）、**定时上报周期**、**指令应答机制**。

3. **业务控制逻辑与权限边界**
   - **门的自动关闭**：目前入户门和车库门开门 `5秒` 后均会自动关门，软件端是否需要“远程控制常开/手动关门”？
   - **模式冲突优先级**：目前语音开关灯/风扇只覆盖 `5秒` 后恢复 `AUTO`，而串口指令会保持手动模式。软件远程下发控制后，与本地语音/自动逻辑的优先级如何约定？
   - **控制粒度扩展**：
     - 风扇是否需要多档调速（当前固定 PWM=`100`）？
     - RGB 灯带是否需要控制全部 `8` 颗灯珠及颜色（当前仅亮第 `0` 颗暖色）？
     - 车库 RFID 是否需要开启 UID 白名单校验或由软件端鉴权？
     - 入户门密码（`4321`）和车库密码（`1234`）是否需要支持软件动态修改？

4. **本地操作的反向事件同步**
   - 当用户在硬件端**按键盘输密码开门、刷 RFID 卡开门、或使用语音控制**时，是否需要硬件主动上报事件通知电脑与香橙派刷新 UI 状态（如刷卡 UID 记录、密码错误告警等）？
