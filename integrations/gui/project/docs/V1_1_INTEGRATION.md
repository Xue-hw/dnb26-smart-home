# v1.1.0 GUI 联调说明

原有 API 路径和主要字段保持兼容，详见 GUI_API_CONTRACT.md。请以 src/types/contracts.ts 为字段定义来源。

## 命令状态（已实现）

POST /api/devices/:id/commands 必须返回 command_id 和 status。
- acked：设备已经确认，可提示成功；随后重新获取快照。
- pending：GUI 每秒 GET /api/commands/:id 查询，最长约30秒；单次 HTTP 请求还有15秒网络超时，因此最后一次请求可能延长总等待。
- failed：展示 error_message 或执行失败。
- timeout 或等待超限：展示结果未知，提示刷新核对，不自动重发指令。

后端应把“已接收”表示为 pending，而非 acked。相同设备等待期间禁用重复操作；状态查询失败不代表硬件未执行。

门窗 position 只能明确返回 open / closed；缺失、未知或离线均不会当作关闭。在线状态及 snapshot.freshness 应准确反映硬件/采样情况，而非仅 HTTP 服务可达。

连接/快照请求失败时保留旧快照并显示提示，禁止首页设备控制。GUI 每30秒刷新，并接受事件触发刷新。

## B1 自动温控（展示区预留）

当前不假定阈值、不执行浏览器端自动控温，固定显示待接入。需双方确认：阈值、自动/手动模式、启动原因、设备确认时间及采样过期规则，再扩展契约和展示逻辑。

## B2 人脸与门禁（部分展示已实现，执行回执预留）

现有 FaceVerifyResult.matched、user_name、message、mode 用于身份结果。mock 响应不显示真实核验通过。
GUI 不会根据 matched 自行发开门命令。门禁执行区独立显示待接入。
后续需补充可区分未检测到人脸/未授权/识别错误的结果码、关联命令ID和实际门禁执行状态。验收两名授权人员和一名未授权人员时，分别核对身份结果与物理门状态。

## B3 照片归档（可选扩展已支持）

CameraSnapshot 原字段保留，新增可选字段：
- saved?: boolean：true 才表示后端确认保存，false 表示未保存，缺省表示等待保存回执。
- archive_url?: string：仅在 saved 为 true 且地址存在时提供查看归档照片按钮。

image_url 只表示可预览，不能据此推断已归档。captured_at 显示拍摄时间。
上传图的持久化与真实拍照、本地磁盘存储由后端负责。

## 人员照片

新增人员只接受不超过8 MB的 JPEG/PNG/WebP；显示预览。后端仍须校验 MIME、文件内容和大小。
人员列表使用 avatar_url；失败则回退姓名字。feature_version 本身不足以证明人脸已录入，因此真实模式的人脸录入状态暂显示待后端确认。后续约定独立 enrollment_status 再接入。

## B5 历史分页

设备与识别记录分别请求 page、page_size=20；共用页码控件，页数取二者最大页数，数量较少的列表可能在后面页为空。
返回准确 total；时间边界按 ISO UTC 传入，界面显示浏览器本地时间。筛选条件只有查询成功才成为已查询条件，翻页沿用已查询条件。

B4后续增强需补齐区间起点状态、完整分页事件和采样规则，才能可靠推算开关持续时间与亮度趋势，不能仅根据一页事件补画连续状态。
