# GUI 2.1 系统整合

GUI 复用原有 React/Vite/Capacitor 工程，对接香橙派上的实际 FastAPI/MySQL 服务。

## 数据来源与连接

- 默认使用 `http` 模式。同源网页将后端地址留空，浏览器通过 `/api/`、`/uploads/` 和 Nginx 代理访问后端。
- 可在“系统与报警”页面输入后端源地址，例如 `http://192.168.137.2:8080`。地址不得包含用户名、密码、路径、查询参数。
- 前端 Mock 模式须明确选择；真实后端故障不会自动切换为演示数据。后端的 `hardware_mode=mock` 或快照 `freshness=mock` 会单独标为硬件模拟，提示 Arduino 尚未接入。
- 管理员令牌通过 Bearer 请求头发送，仅存当前会话的 sessionStorage；不写入 localStorage、URL、静态资源或源码。清空令牌并保存后返回未认证状态。
- SSE 与 MJPEG 为只读通道，不通过 URL 传递令牌。后端需要允许 Android WebView 的 `https://localhost` origin。

## 识别和门禁

- 实时共享输入：`GET /api/camera/stream` 提供 MJPEG；`GET /api/vision/live` 提供对应帧编号、时间、物体与人脸状态。
- 页面将“身份匹配”“当前会话眨眼”“通行资格”“控制器执行回执”分别展示。
- 静态照片只核对身份，始终显示“静态照片不予通行”。
- 实时数据查询失败或帧时间过期后，移除之前的通过结果。人脸结果独立检查 `face_captured_at`；YOLO 仍更新时，过期或缺少时间的人脸结果也不显示通行。
- 新鲜度使用同一服务端时钟的 `server_time - captured_at`，加上客户端接收后的单调经过时间和整段请求往返时间。客户端与板端日期不一致不会使新帧永远过期；缺少服务端时间、异常未来时间、慢请求或旧帧均不能显示通行。
- 控制器 ACK 只代表控制器确认；当前门没有门磁或限位，物理到位需现场观察。
- 模拟回执明确显示 Arduino 尚未接入。同一人员进入新会话后，新命令不会继承上一条命令的 ACK。
- 抓拍保存结果使用后端 `saved/archive_url` 回执；页面预览不冒充文件保存成功。

## 状态和报警

首页与系统页显示后端报警，确认报警只表示已阅读，不代表已恢复。系统页列出后端、MySQL、摄像头、Arduino 与模型状态，并提供温控启停阈值、门未关提醒、灯泡联动、照片保留天数配置。无管理员权限时不允许保存后端配置。

传感器历史支持温度、湿度、烟雾、雨滴和光照指标；没有实际数据时显示无数据，不生成伪读数。

双 UNO 接入时，首页和系统页分别显示 `hardware_boards.uno1/uno2` 的在线状态。设备通过 `board_id` 绑定板卡，所属板离线时禁用控制，即使旧设备状态仍为 online。车库门使用 `garage_door`、`kind=door`，移动中禁用切换。`state.state_basis=actuator` 表示执行器反馈，界面不据此确认物理门位置。设备 `capabilities` 不含 brightness 时隐藏亮度控制；auto/manual 显示当前模式；具备 mode 能力的灯光与风扇支持“恢复自动”，只发送 set {mode: auto}，手动开关与亮度请求不额外附加 mode 字段。未获得写权限、离线、所属板掉线或等待命令时均禁用控制。真实模式默认仅列温度、湿度、光照及后端实际返回的传感器指标，不预置烟雾、雨滴设备；未接窗户作为装饰窗展示。

gateway 温控阈值输入精度为 0.1°C。保存成功表示后端已保存期望值，界面同时显示 UNO1 报告的实际阈值；只有板在线、固件确认同步且实际值与后端已保存值相符时显示“已同步”。未保存的编辑值不会改变同步状态。UNO1 本地执行自动温控，语音临时操作 5 秒后恢复此前模式与设置。

历史默认范围、重置和最近1小时／24小时／7天使用设备 `server_time` 与客户端单调时钟计算，页面首次进入等待有效设备时钟。设备与浏览器时钟偏差超过2分钟时显示提示；输入和记录仍按浏览器时区显示，手动输入的日期按原值查询，设备状态刷新不会改写已编辑的筛选条件。

## 已接硬件的扩展控制

首页按设备 capabilities 展示灯带 color、led_count（1–8 个）、风扇 speed（0–100 整数）和两扇门 pin。各按钮使用 action=set，params 只包含本次修改的一个字段；没有相应能力时不出现控件。离线、所属 UNO 掉线、未获得写权限或该设备命令待确认时禁用操作。目标输入与当前反馈分别显示，界面不会把未报告值当作硬件实测值。

PIN 只提供 4 位数字的掩码输入，不读取旧 PIN，不持久保存输入，控制器确认成功后清空；状态文本忽略意外返回的 pin 字段，失败消息使用固定安全文案，不回显请求内容。PIN 的协议、保存与脱敏由后端和网关负责。

系统配置通过请求序列隔离刷新与保存：保存开始后，旧的检查服务响应不能覆盖较新的后端期望值；保存等待期间禁止发起配置刷新。测试覆盖旧 GET 后于新 PUT 返回的精确时序，防止同步状态错误回退。
## Android

Android 版本为 `2.0.0`，versionCode 为 `200`。网络配置默认禁止明文 HTTP，仅允许课堂联调主机 `192.168.137.2`、localhost、127.0.0.1 和模拟器主机 10.0.2.2。其他后端需 HTTPS，或由维护者明确更新允许主机列表后重建。LAN HTTP 支持所需的 mixed-content 配置受上述主机范围限制。正式跨网络使用应选 HTTPS/VPN。

真实 APK 构建时设置 `VITE_DATA_MODE=http` 与板端地址 `VITE_API_BASE_URL`；Web 同源构建时留空该地址。环境变量是编译时值，运行时连接设置可覆盖。

## 2.1 界面与验证

米白/橄榄绿控制台和可旋转、缩放、切视角的 Three.js 房屋。入户门、车库门、灯光和风扇使用实际反馈；未知门状态隐藏门片并显示未知。WebGL 不可用或上下文丢失时保留文字设备状态及控制。模型按需加载，最大1.5倍像素比、30fps，后台页停止渲染，减少动态偏好下停风扇动画。首次安装的原生 APK 默认连接 http://192.168.137.2:8080；Web 默认同源，用户保存地址优先。

电脑网页与手机 APK 需要分别测同一后端下的双向状态、历史及报警同步，浏览器模拟移动端不代替实体 APK 结果。参见仓库 docs/联调测试表.md 与 CSV。
